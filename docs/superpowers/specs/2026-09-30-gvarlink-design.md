# GVarLink: a bounded persistence companion to gvar

Status: proposed component specification, 2026-09-30. This supersedes only the bridge portion of the rejected CovWeave engine design. No academic novelty, external demand, production readiness, or project-count claim.

## Workflow and distinct value
Two independent reduction jobs use an agreed source declaration for a shared dark/calibration measurement and fresh UUIDs for independent exposures. Each computes with ordinary gvar objects, writes a numeric-only artifact, and exits. A third job validates both artifacts before allocating their numeric arrays, reconciles declarations, restores both into one gvar context, and computes a contrast with its cross-covariance intact. Equal labels/numbers never imply shared uncertainty. A source UUID with a changed latent basis is an error. Loading into separate contexts intentionally does not correlate them.

The predecessor experiment establishes that gvar already does the numerical job and that an explicit adapter can carry it across files. GVarLink contributes an auditable closed format, resource admission, identity contract and reproducible cross-process tests. RMEllipse already offers source-preserving HDF5 restart; users satisfied by it or gvar's joint native serialization do not need this component. This is a useful compatibility experiment, not evidence that a new engine or standalone major project is justified.

## Alternatives and choice
1. Native gvar joint serialization: smallest solution for jointly available results; retain this recommendation whenever separate jobs do not require shared identities.
2. Adopt RMEllipse: existing mechanism-identity persistence, strongest choice for workflows already using its model; explicitly credited.
3. A gvar companion (chosen conditional scope): preserve existing gvar analysis code and add a strict declared identity envelope. More format maintenance; justified only for separate-job interoperability and a data-only untrusted-input boundary.

## Scope
One Python package, API, inspect/verify/demo CLI, original synthetic branch and masked conservative-counts-rebin examples, native gvar interoperability and standard-library reference reader. No covariance engine, general array class, transformation DSL, automatic scientific identity inference, factor rotation, unknown correlated blocks, arbitrary nonlinear moment correction, remote source fetching, custom callable loading or binary dependency vendoring. CoMet adapter is deferred: the current need is solved by gvar; adding it now expands maintenance without an established workflow.

## Model and identity
A source block is an explicitly declared collection of independent standard-normal latent coordinates. Distinct UUIDs assert mutually uncorrelated blocks. A Source has canonical lowercase UUID, display label, revision, basis description and positive ordered shape (C order). Its basis fingerprint is SHA-256 of a canonical JSON object containing model='independent-standard-normal-v1', revision, description, shape and order='C'. Identity is UUID plus that complete definition. Same UUID with any differing definition fails closed; labels are descriptive and may differ. The fingerprint is an integrity convenience, not proof that two physical measurements are the same. Generate UUID4 once per independent acquisition; share a declaration only deliberately. Coordinate permutations require a new definition/UUID; v1 does not align them. Reordering entire blocks is supported through explicit offsets.

An Artifact contains float64 means, one canonical CSR derivative table against the concatenated block basis, original output shape, unit text, and uncertainty interpretation 'affine' or 'linearized'. 'Affine' is a caller assertion; it is not inferred or validated from gvar expression history. Conservative default is 'linearized'. No recipe is executed. Zero derivative entries are disallowed; per-row columns are strictly increasing and unique. Scalar and empty output shapes are supported. Floating-point finite-only data; overflows fail rather than silently publish infinities. Immutable copies prevent post-validation mutation.

## Public surface
Source.create(label, shape, description, revision='1', uuid=None). Context(sources, limits=...) creates standard-normal gvar primaries; context.primary(source) retrieves them. Context.pack(values, unit='', interpretation='linearized') exports public gvar sparse derivatives and rejects nonzero dependencies outside the context. Context.restore(artifact) reconciles and restores gvar outputs using gvar_function on row-local primaries. load_many(paths) validates all sources before constructing a common context and returns that context plus restored arrays. A Context has a lifetime resource cap, and conflicts do not partially mutate it. Registry identity is never recovered from raw gvar files. Artifact.from_arrays is a bounded explicit interchange API for already-known numeric factors.

read(path, limits=...), write(artifact, path, overwrite=False), inspect(path). CLI: gvarlink inspect PATH; gvarlink verify PATH...; gvarlink demo DIRECTORY. CLI never auto-executes file recipes; no pickle/native gvar deserialization of supplied files.

## Closed file format v1
Single regular file with 8-byte magic 'GVARLNK1', unsigned little-endian 64-bit header length, bounded UTF-8 JSON header, then exactly four contiguous little-endian raw arrays: mean f8[n], indptr u8[n+1], indices u8[nnz], data f8[nnz]. No archive, compression, member paths, dtype strings, executable metadata, NPY parser, URLs or external references. Header contains exact format/version, output shape, source declarations, unit/interpretation, nnz, per-array SHA-256 and payload byte count. A final 32-byte SHA-256 covers magic+length+header+payload. This is corruption detection, not authenticity; an attacker can rehash lies. Unknown versions/fields, duplicates, unexpected bytes, non-finite data, malformed UUID/hash/basis, bad CSR, unsupported model all fail. Future versions require a separately reviewed explicit converter; v1 rejects them.

## Resource and I/O boundary
Defaults: 1 MiB header, 64 MiB entire file, 100,000 output rows, 200,000 total latent coordinates, 2,000,000 nnz, 1,024 blocks, rank <=8, JSON depth <=16, bounded strings. Callers may lower limits; explicit raises remain bounded by hard implementation ceilings. Header lengths, declared dimensions/products, array byte counts, file size and payload checksums are checked before numeric array allocation. JSON is byte/depth bounded before json.loads, duplicate keys and long integer tokens rejected. Reader accepts only a regular local file; no decompression or filesystem extraction. The opened file descriptor is used throughout; truncation and inconsistent trailing bytes fail. No claim that these budgets cap interpreter/gvar/BLAS RSS or defend against malicious same-user OS mutation. Files are untrusted; applications must authenticate the producer and verify scientific identities separately.

Writer validates a snapshot, stages a sibling temporary regular file, flushes/fsyncs, then uses a no-clobber publication step (hard-link where supported) unless overwrite=True authorizes atomic replace. No partial destination on serialization failure, no implicit overwrite. Local filesystem correctness assumed; directory durability/platform semantics documented. Any unsupported safe no-clobber operation fails with actionable error, no unsafe fallback.
